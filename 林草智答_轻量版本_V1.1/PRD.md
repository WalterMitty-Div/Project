## 1. 产品概述

一句话定位：面向林草基层调查与技术人员的智能问答助手，把厚重的技术规程、普查方案和操作手册，变成随问随答、有出处可查的知识服务。

产品不追求"什么都能答"，而是聚焦一件事：**让一线人员用一句大白话，问到规程里的准确答案，并知道答案出自哪份文件。**

产品同时支持两种运行模式：
- 云端大模型：效果最好，适合办公室、网络良好环境。
- 本地小模型：免费、离线、数据不出本机，**适合外业无网络环境**。

## 2. 背景与问题

- 林草调查高度依赖技术规程与普查方案，单册动辄上百页，查阅费时。
- 基层人员流动大、记忆负担重，遇到问题主要靠电话咨询上级或翻找文档。
- 培训成本高，同类问题反复出现，答疑占用内业人员大量精力。
- 因子填写不规范导致数据返工，影响成果质量与进度。
- 外业现场常常没有网络，云端 AI 方案无法使用。

## 3. 目标用户与使用场景

| 用户 | 场景 | 期望 |
|---|---|---|
| 外业调查员 | 现场忘记某因子填写规则，且现场无网络 | 用手机或平板提问，即时得到答案与规程出处 |
| 新入职人员 | 学习调查规程与作业流程 | 通过多轮问答快速上手 |
| 内业质检人员 | 查询质检规则、字段定义 | 少翻文档，快速定位条款 |

## 4. 产品目标

- 核心目标：让用户的提问得到**有出处支撑的准确答案**。
- 成功标准：
  - 演示场景下，常见问题能被正确回答且能定位到来源文档。
  - 用户从提问到看到答案的时间在可接受范围内（秒级响应）。
  - 超出知识范围的问题，能如实说明而不是编造。
  - 本地小模型模式下，在无网络环境也能正常问答。

## 5. 界面结构

应用分为三个页面，顶部导航切换：

| 页面 | 内容 |
|---|---|
| 聊天 | 对话区与输入框，显示当前使用的模型模式 |
| 知识库 | 上传文档、构建知识库、查看知识库状态 |
| 设置 | 模型设置：切换云端大模型 / 本地小模型，配置接口地址、模型名、API Key |

设置项保存在浏览器本地，切换页面不丢失。

## 6. 功能需求

优先级说明：P0 必须有，P1 应该有，P2 可以有。

### P0｜F1 文档上传与知识库构建
- 描述：用户上传规程、方案、手册（支持 docx、txt、md），系统解析并切分，构建可检索的知识库。
- 验收：上传一份 docx 后，提示"知识库已就绪，共 N 个片段"。

### P0｜F2 智能问答
- 描述：用户用自然语言提问，系统先检索知识库，再调用大模型组织答案。
- 验收：对知识库中有的问题能给出正确答案，且不超出资料范围作答。

### P0｜F3 引用溯源
- 描述：每条答案可展开查看命中的原文片段及来源文件。
- 验收：引用内容与答案相关，来源文件名正确。

### P0｜F4 转人工兜底
- 描述：当问题超出知识范围，或涉及投诉、人工等关键词时，提示转接人工。
- 验收：输入包含"投诉""人工"等词时，返回转人工提示。

### P0｜F11 大模型 / 小模型切换
- 描述：在设置页一键切换"云端大模型"与"本地小模型"，自动填入对应的接口地址、对话模型与向量模型。
- 交互：选择模式 → 自动填预设 → 可手动微调 → 保存。
- 验收：切换模式后，聊天页顶部正确显示当前模式；本地模式下无需 API Key 即可问答。
- 说明：本地小模型需用户预先安装 Ollama 并拉取模型。

### P0｜F12 三页面导航与配置持久化
- 描述：聊天、知识库、设置三个页面导航切换，设置本地保存。
- 验收：刷新页面后设置仍在。

### P1｜F5 多轮对话记忆
- 描述：记住上下文，支持追问（如"那这个字段呢？"）。

### P1｜F6 业务分类知识库
- 描述：按样地调查、古树名木、湿地、荒漠化等业务分别建库，提问时自动路由到对应库。

### P1｜F7 会话历史
- 描述：保存历史会话，可回看与继续。

### P2｜F8 语音输入
- 描述：外业现场可用语音提问。

### P2｜F9 答案反馈
- 描述：用户对答案点赞/点踩，用于后续优化。

### P2｜F10 多用户与权限
- 描述：支持多人使用与角色区分。

## 7. 非功能需求

- 准确性：答案必须有出处，降低模型幻觉。
- 响应：采用流式输出，避免长时间空白等待。
- 易用：界面简洁，手机端可用。
- 部署：优先一键本地运行，降低使用门槛。
- 离线：本地小模型模式下，全程无需联网即可使用。

## 8. 技术方案

- 架构分层：界面层（三页面） / 服务层（会话与编排） / 智能层（检索与大模型） / 数据层（语料、向量、会话）。
- 技术栈（当前 MVP）：
  - 界面与服务：Python + Flask，页面内嵌
  - 模型接入：兼容 OpenAI 接口规范，云端（通义千问等）与本地（Ollama）共用一套调用逻辑
  - 检索：向量相似度检索，标准库实现
  - 文档解析：标准库解析 docx
- 问答流程：文档解析 → 文本切分 → 向量化 → 存入向量库 → 提问向量化 → 相似检索 → 拼接提示词 → 大模型生成 → 标注出处。
- 选型理由：采用检索增强而非模型微调，规程可随时更新、成本低、答案可溯源；答案主体来自检索到的原文，因此对模型规模要求不高，本地小模型即可胜任。

## 9. 数据来源

- 一线人员测试反馈中的真实问题清单（可作为问答评测集）

## 10. 范围边界

- 本期包含：本地知识库问答、引用溯源、转人工提示、大小模型切换。
- 本期不含：对接真实业务平台、复杂 Agent 工具调用、多租户、移动端原生应用、模型微调。

## 11. 验收标准

- 上传至少 3 份林草文档后，能正确回答 10 个预设问题中的绝大多数。
- 每个答案都能定位到具体来源文件。
- 超出范围的问题不编造，能如实说明或转人工。
- 本地小模型模式下，断网仍可完成一次完整问答。
